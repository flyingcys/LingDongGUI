# TinyUI v2.3 总编排实施计划

> **面向代理执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务执行。步骤使用复选框跟踪。

**目标：** 在不处理 port 生产化的前提下，一次性把 TinyUI 收口为面向小型 MCU 的轻量、统一、真实 LingDongGUI 封装，并只冻结一套 canonical ABI。

**架构：** 严格按 `M0 -> M1 -> M2 -> M3 -> M4 -> M5` 串行推进。M0/M1 冻结事实和契约，M2 用四个样板控件验证直接映射，M3 才并行迁移全控件，M4 迁移消费者，M5 统一硬化和冻结。LingDongGUI tree、layout 和 renderer 始终是唯一真实实现。

**技术栈：** C11、CMake、CTest、Python 3、LingDongGUI、Arm-2D、SDL2 测试宿主、Clang ASan/UBSan、GitNexus。

## 全局约束

- 不创建 worktree。
- 所有 shell 命令以 `rtk` 开头。
- 所有 markdown 文档使用中文。
- 修改函数前必须运行 GitNexus upstream impact。
- `HIGH/CRITICAL` 风险必须先告警并形成调用者迁移清单。
- TinyUI 不建立第二套对象树、renderer、layout solver、style selector、事件传播或资源中心。
- 基础 wrapper 不超过 `192 B`；backend widget 不超过 `512 B`。
- 32 位 ABI runtime pool 不超过 `1024 B`。
- steady-state `tinyui_process()` 隐式 heap 分配为 `0`。
- 未启用控件和模块不得进入最小裁剪二进制。
- required 能力达到 L4；可见能力达到 L5-V；可操作能力达到 L5-E。
- port 相关 L6 证据不属于 v2.3。
