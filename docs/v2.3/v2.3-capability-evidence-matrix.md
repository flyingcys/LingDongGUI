# TinyUI v2.3 能力证据矩阵

## 目的

本文件定义 v2.3 的人工可读能力关门矩阵。机器真相仍由 M0 从当前 LingDongGUI public headers 重新生成；本文件不得替代源码 inventory、gap ledger 和 release matrix。

当前 JSON 的 `629/629` 只表示旧清单已分类，不表示 v2.3 语义已闭环。M0 源码扫描已知会发现至少四个旧冻结清单外符号，因此所有“当前覆盖”数字只作为历史基线。

## 证据等级

| 等级 | 要求 |
| --- | --- |
| L1 | canonical public 声明存在 |
| L2 | 独立 C/C++ consumer 可编译、链接 |
| L3 | 参数、错误、容量、所有权和裁剪语义正确 |
| L4 | 真实 LingDongGUI 对象状态发生预期变化 |
| L5-V | 用户可见能力有确定像素证据 |
| L5-E | 用户可操作能力有真实事件证据 |
| L6 | 目标 port 上的资源、时序和生命周期证据 |

v2.3 只关闭 L1-L5。L6 明确延期。

## 单项记录格式

机器矩阵中的每项 required 能力必须记录：

```json
{
  "capability_id": "widget.property_or_action",
  "canonical_api": "tinyui_xxx",
  "required": true,
  "evidence": {
    "l1_header": "path:symbol",
    "l2_link_test": "ctest-name",
    "l3_contract_test": "ctest-name",
    "l4_native_test": "ctest-name",
    "l5_visual_test": "ctest-name-or-null",
    "l5_event_test": "ctest-name-or-null"
  },
  "port_l6": "deferred"
}
```

`null` 只允许用于能力本身不具有对应视觉或交互维度，不允许用来跳过应有证据。

## 关门规则

- M0：矩阵行必须来自当前源码，数量与 inventory 一致。
- M2：四个样板控件和共享核心行关闭。
- M3：全部控件行关闭。
- M5：每个 required 项都有可执行证据引用，人工 review 逐项抽查。
- 任一 required 项缺 L4，或可见/可操作项缺对应 L5，v2.3 不得关闭。
