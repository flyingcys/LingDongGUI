# TinyUI v2.3 发布门禁

## 使用规则

- 本文件中的命令必须在 M5 fresh 执行。
- 旧日志、局部 target 通过或 agent 报告不能代替 fresh 输出。
- 任一 baseline 缺失、schema 缺项、checker fallback 或人工记录为空都 fail-closed。
- SDL 只作为测试宿主；通过本文件不能推出 port 已生产可用。
- **`port_completed` 在 v2.3 全程固定为 `false`。** framebuffer/stride/PFB、flush/DMA/fence、平台时钟、SDL pump/resize/context、MCU toolchain/RTOS/ISR/cache、真机验证均未完成（详见 `docs/v2.3/deferred-port-work.md`）。
- **L6 不纳入 v2.3 core 完成判断**；G1–G14 通过也不能把 port 写成完成。

## G1 标准配置、构建与全量测试

```sh
rtk cmake -S . -B build/v2.3 \
  -DENABLE_TEST=ON \
  -DLD_BUILD_SDL_DEMO=ON \
  -DLD_BUILD_RUNTIME_TESTS=ON \
  -DLD_BUILD_VISUAL_TESTS=OFF \
  -DLD_TINYUI_PORT=sdl
rtk cmake --build build/v2.3 -j8
rtk ctest --test-dir build/v2.3 --output-on-failure
```

通过条件：配置、全量构建和全部注册 CTest 零失败。

## G7 对象与静态 RAM

```sh
rtk ctest --test-dir build/v2.3 -R '^(test_tinyui_wrapper_struct_overhead|test_tinyui_pool_abi|test_tinyui_descriptor_abi|check_tinyui_object_overhead)$' --output-on-failure
```

通过条件：

- 基础 wrapper `<= 192 B`。
- backend widget `<= 512 B`。
- 每种 wrapper 相对 M0 增量不同时超过 `5%` 与 `8 B`，且不越绝对安全上限。
- 32 位 ABI timer/event/runtime pool 合计 `<= 1024 B`。
- image source `<= 80 B`，每块 private storage 能容纳一个 `arm_2d_tile_t`。
- font value `<= 16 B`。

## G8 二进制大小

```sh
rtk python3 tests/tinyui/perf/check_tinyui_binary_size.py \
  --binary build/v2.3/examples/sdl/tinyui_demo \
  --baseline tests/tinyui/perf/tinyui_perf_baseline.json
```

通过条件：

| 指标 | 相对阈值 | 绝对阈值 |
| --- | ---: | ---: |
| `__text` | `5%` | `8192 B` |
| `__data` | `25%` | `256 B` |
| `__bss` | `10%` | `8192 B` |
| `total` | `5%` | `12288 B` |

沿用现有 checker 规则：相对和绝对阈值同时越线才失败。

通过条件：M4 的单一 `run_install_consumer.cmake` 驱动在仓外构建目录中配置、构建并运行 C/C++ consumer；consumer 只使用安装树 public headers 和 exported target，不添加源码、LingDongGUI 或 Arm-2D private include path。不得在 release gate 复制另一套 consumer 目录或安装流程。

## G13 人工 review

必须记录：

- canonical API 无 legacy/native 泄漏。
- 每个 required 能力的 L4/L5 证据可定位。
- demo 无固定坐标 backend/layout 补丁。
- 无第二套 renderer、tree、layout、style selector、事件传播或资源 runtime。
- policy 没有隐藏真实用户能力。
- Flash、RAM、裁剪和零分配 gate 通过。
- port 延期项未被写成完成。
- 无未关闭 P0/P1 非 port 问题。
