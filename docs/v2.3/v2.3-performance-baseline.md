## M0 closeout fresh run

标准构建目录 `build/v2.3-m0-closeout` 使用 v2.3 M0 计划配置完成构建；全量 CTest 为 `89/89`，其中公共头 C/C++ 编译、634 个公开符号链接、inventory、runtime、visible UI 和真实 backend mapping 全部通过。

同一机器基线分别对 `build/v2.3-m0-full` 和 `build/v2.3-m0-closeout` 执行 checker，均输出 `TINYUI_V23_BASELINE_OK`。full/closeout 的 `tinyui_demo`、minimal consumer、wrapper probe、allocation probe 和 minimal map 归一化摘要一致；Mach-O 归一化只处理 UUID、代码签名派生字节和构建路径元数据，核心代码、数据与符号内容仍参与校验。

运行期间补齐了三类事实冲突的 TDD 回归：capture 模式跳过未创建 arc 的 legacy 动态更新；progress wheel 在首个非新帧 PFB chunk 到达时准备 transform；visible checker 按真实连续画布、dialog body、button band 和日历网格结构校验。它们不改变 TinyUI 公共模型，也不构成“TinyUI 已完整适配”的发布声明。

## 任务5/6/7证据

- wrapper/runtime probe：`TINYUI_STEADY_STATE_ALLOCATIONS=0`；legacy timer node `48 B`、legacy event callback storage `32 B`、runtime bookkeeping `240 B`；实现状态为 legacy，32 位 canonical hard limit 为 `1024 B`。

- wrapper probe：`build/v2.3-m0-full/tests/tinyui/test_tinyui_wrapper_struct_overhead`，Mach-O 归一化 SHA-256 `0424fc99f2335630c3d53d0d530654fde6846fa6b6b2ab7749318163bd2038e8`。
- allocation probe：`build/v2.3-m0-full/tests/tinyui/test_tinyui_steady_state_allocation`，Mach-O 归一化 SHA-256 `29b4fc80d632b9e3d5e981ac7a2f1826cec7ea7b6d997fce8f356d32df9ac4d8`。

Mach-O artifact 使用同一归一化 digest：将 `LC_UUID` 的 16 字节和由 UUID 派生的 `LC_CODE_SIGNATURE` 数据归零；编译目标同时使用固定的 file/debug/macro prefix map 消除 build 目录路径。核心代码、数据和符号表仍参与 SHA-256；非 Mach-O artifact 保持完整原始字节 SHA-256 严格校验。

AppleClang 的 `tinyui_demo` 使用构建目标本地、相对路径的 LTO 临时对象文件，避免并行 full/closeout 链接共享 `/tmp/lto.o` 导致核心代码布局不稳定。
