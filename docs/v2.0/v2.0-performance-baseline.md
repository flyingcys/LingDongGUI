## 基线对象

- 目标二进制：`build/picoui-runtime/examples/sdl/picoui_basic_widgets_demo`
- 基线命令：`xcrun llvm-size --format=sysv build/picoui-runtime/examples/sdl/picoui_basic_widgets_demo`
- 口径说明：
  - 本机 `size` 默认输出是 Mach-O segment 汇总，不是 GNU `text/data/bss/dec`
  - `P5` 的 `Binary Size` gate 统一冻结四个归一化指标：`__text`、`__data`、`__bss`、`total`
  - Mach-O `llvm-size --format=sysv` 输出会把 `__text/__data/__bss/Total` 映射到这四个指标
  - GNU `size` 或 ELF `llvm-size --format=sysv` 输出会把 `.text/.data/.bss/dec|Total` 映射到同一组指标
  - macOS 若只跑默认 `size`，不能直接拿 `__TEXT/__DATA` segment 汇总替代上述基线

## 阈值策略

- 阈值文件：`tests/picoui/perf/picoui_tinyui_perf_baseline.json`
- schema 要点：
  - `binary_size.metrics` 必须完整包含 `__text`、`__data`、`__bss`、`total`
  - 每个 metric 都必须显式提供 `baseline_bytes`、`max_increase_percent`、`max_increase_bytes`
- 判定方式：每个指标都采用“双阈值并联放行”
  - 百分比阈值：允许相对 baseline 的有限增长
  - 绝对字节阈值：限制小基数指标被百分比口径放大
- 越线规则：只有当“增长字节数”同时超过百分比换算上限和绝对字节上限时，checker 才判失败

| 指标 | baseline | 百分比阈值 | 绝对字节阈值 |
| --- | ---: | ---: | ---: |
| `__text` | `121844` | `5%` | `8192` |
| `__data` | `272` | `25%` | `256` |
| `__bss` | `98768` | `10%` | `8192` |
| `Total` | `231400` | `5%` | `12288` |

## 当前 gate

- checker：`python3 tests/picoui/perf/check_picoui_tinyui_binary_size.py`
- baseline：`tests/picoui/perf/picoui_tinyui_perf_baseline.json`

## Runtime Perf

- checker：`python3 tests/picoui/perf/check_picoui_tinyui_perf.py`
- 基线来源：`tests/picoui/perf/picoui_tinyui_perf_baseline.json -> benchmark.runtime_perf.metrics`
- 当前口径：
  - `screen_object_create_ms`：`picoui_screen_create()` 返回 root screen object 的创建耗时；只覆盖 runtime public API 侧 screen wrapper/root window 建立，不宣称包含后续渲染
  - `capture_ready_ms`：`picoui_screen_load()` 完成后开始计时，到 benchmark 检测到 `PICOUI_CAPTURE_FILE` 已真实生成且尺寸有效为止；它证明“capture 已可读”，不宣称是真实首帧渲染完成时间
  - `basic_widgets` benchmark 载体已收回到纯 `picoui_*` public API 用户路径；为保持现有 runtime checker 兼容，demo 仍额外输出旧 benchmark marker 作为兼容别名，但 `P5` checker/baseline 只认上述新口径名
- fail policy：
  - baseline 缺 `benchmark.runtime_perf.metrics` 任一必需项时，checker 直接失败
  - 不允许默认 fallback 继续通过

| 指标 | baseline | 上限 |
| --- | ---: | ---: |
| `screen_object_create_ms` | `0.0 ms` | `5.0 ms` |
| `capture_ready_ms` | `20.0 ms` | `40.0 ms` |

## Wrapper Struct Overhead

- checker：`python3 tests/picoui/perf/check_picoui_tinyui_object_overhead.py`
- 基线来源：`tests/picoui/perf/picoui_tinyui_perf_baseline.json -> benchmark.wrapper_struct_overhead.metrics`
- 口径说明：
  - 该 gate 是 ABI-bound struct footprint guard，只量编译期 `struct` 布局大小，不量 runtime heap、native widget 实例树、allocator bookkeeping，也不外推“全控件族 RAM 成本”
  - checker 先 configure/build 正式 probe target `tests/picoui/unit/test_picoui_wrapper_struct_overhead.c`，再执行 target 读取 marker；不再依赖 `compile_commands.json` 或临时写 C 文件
- fail policy：
  - baseline 缺 `benchmark.wrapper_struct_overhead.metrics` 任一必需项时，checker 直接失败
  - 不允许默认 fallback 继续通过

| 指标 | baseline | 上限 |
| --- | ---: | ---: |
| `widget_wrapper_struct_bytes` | `184` | `192` |
| `switch_wrapper_struct_delta_bytes` | `32` | `32` |
| `backend_widget_struct_bytes` | `496` | `512` |

## P6 Blocking Policy

- `binary_size`、`runtime_perf`、`wrapper_struct_overhead` 任一 gate 越线，必须阻塞 `P6`
- 未形成 baseline 真值、schema 缺项、checker 回退到隐式默认值，也必须阻塞 `P6`
- 当前 `runtime_perf` / `wrapper_struct_overhead` 已有 focused gate，但它们仍只证明各自明确定义的窄口径，不得外推成完整首帧渲染或整体 RAM 成本结论

## 当前结论

- `P5` 当前可以保守确认已完成：
  - `binary_size`、`runtime_perf`、`wrapper_struct_overhead` 三条守门线都已具备 baseline、checker 与 fail-closed policy
  - `python3 tests/picoui/perf/check_picoui_tinyui_binary_size.py`
  - `python3 tests/picoui/perf/check_picoui_tinyui_perf.py`
  - `python3 tests/picoui/perf/check_picoui_tinyui_object_overhead.py`
  - `rtk ctest --test-dir build -L 'perf' --output-on-failure`
  - `rtk ctest --test-dir build/picoui-runtime -R 'check_picoui_runtime|check_picoui_visible_ui|check_picoui_backend_mapping' --output-on-failure`
  - 当前 checkout 上述 fresh gate 均已通过
- `P5` 当前不能外推成以下结论：
  - 完整首帧渲染时间已经被证明
  - 整体 RAM 成本或所有控件族开销已经被证明
  - 后续版本不再需要继续维护这些 baseline 与阈值
