## a-0.4 线定位

`a-0.4` 线不是“再包四个控件”。

它是 TINYUI 的输入 shared-core 线，只做一件事：

1. 先把输入/焦点/选择的 shared-core 做实。
2. 再在这套 shared-core 上串行接入 `line_edit / keyboard / combo_box / scroll_selecter`。

## a-0.4 线做什么

1. 清理 runtime 的通用补 layout 路径，恢复 backend/layout honesty。
2. 冻结 getter truth policy：哪些回 backend，哪些只是 host cache，哪些暂不暴露。
3. 建立 focus ownership。
4. 建立 editable text contract。
5. 建立 keyboard bridge。
6. 建立 selection / navigation contract。
7. 建立 dropdown contract。
8. 串行接入 `line_edit / keyboard / combo_box / scroll_selecter`。

## a-0.4 线不做什么

1. 不做 `table / graph / calendar`。
2. 不做 `arc / gauge / icon_slider / radial_menu`。
3. 不允许用 demo 硬编码或 runtime 补位制造 visible PASS。
4. 不允许把 host cache getter 写成 backend truth。
5. 不允许四个控件并行平推。

## 严格串行顺序

固定顺序：

1. `a-0.4-R0 honesty + readback policy`
2. `a-0.4-R1 focus ownership`
3. `a-0.4-R2 editable text contract + line_edit`
4. `a-0.4-R3 keyboard bridge + keyboard`
5. `a-0.4-R4 selection / navigation contract`
6. `a-0.4-R5 dropdown contract + combo_box`
7. `a-0.4-R6 scroll_selecter`
8. `a-0.4-R7 matrix / gate / docs closeout`

顺序原因：

1. 不先处理 `R0`，visible/gate 还会继续把补位后的 UI 当成真实结果。
2. 不先处理 `R1`，`line_edit` 和 `keyboard` 会互相卡住。
3. 不先处理 `R4`，`combo_box` 与 `scroll_selecter` 会各自重造 selection 逻辑。

## subagent 串行拓扑

   - 做最终验证
2. `SG-0.4-R0`
   - 只做 honesty + readback policy
3. `SG-0.4-R1`
   - 只做 focus ownership
4. `SG-0.4-R2`
   - 只做 editable text + `line_edit`
5. `SG-0.4-R3`
   - 只做 keyboard bridge + `keyboard`
6. `SG-0.4-R4`
   - 只做 selection / navigation
7. `SG-0.4-R5`
   - 只做 dropdown + `combo_box`
8. `SG-0.4-R6`
   - 只做 `scroll_selecter`

   - 每阶段独立 review

规则：

1. 任意时刻只允许一个写 subagent。
2. review 不通过，由同阶段 subagent 修，不新开主线程修。
3. 阶段间必须主线程验收后再进入下一阶段。

## 每阶段最小验收

每阶段结束至少执行：

```bash
rtk cmake -S . -B build -DUSE_DEMO=0
rtk cmake --build build
ctest --test-dir build -L tinyui --output-on-failure
python3 tests/tinyui/contract/check_tinyui_public_api.py
git diff --check
```

涉及 mapping / visible / runtime / release matrix 时，再追加：

```bash
python3 tests/tinyui/contract/check_tinyui_release_capability_matrix.py
python3 tests/tinyui/runtime/check_tinyui_backend_mapping.py
python3 tests/tinyui/runtime/check_tinyui_visible_ui.py --all
python3 tests/tinyui/runtime/check_tinyui_runtime.py
```

对 `R0 / R1 / R4` 必须额外验证：

1. frame/event 后 getter 与 backend truth 一致
2. hidden / disabled / focus transfer 不失真
3. 不再依赖通用补 layout 逻辑

## closeout 标准

`a-0.4` 完成时至少要满足：

1. `line_edit / keyboard / combo_box / scroll_selecter` 全部进入 TINYUI public widget。
2. 输入 shared-core 不再依赖 demo 补丁或 runtime 补位。
3. getter truth policy、matrix、中文文档完全一致。
4. `a-0.5` 可以直接拿 `focus / edit / navigation` 合同做输入前置，不再返工 `0.4`。

当前代码/验证状态：

1. `line_edit / keyboard / combo_box / scroll_selecter` 已全部进入 TINYUI public widget。
2. `check_tinyui_backend_mapping.py` 已覆盖 `line_edit_basic / combo_box_basic / scroll_selecter_basic` 的真实 backend mapping。
3. `check_tinyui_visible_ui.py` 已覆盖 `line_edit_basic / combo_box_basic / scroll_selecter_basic` 的自动可见证据。
4. `check_tinyui_runtime.py` 继续覆盖 `keyboard_basic` 的 ownership/bridge runtime 证据。
5. 当前 final release matrix 已把这四个控件统一纳入 `full_parity_complete`，但 `keyboard` 仍保留 runtime-first、manual-artifact-required 的 special-case 证据边界。

当前 review 保留问题：

1. `keyboard` 的 release 证据现已回调到 runtime-first 口径；当前仍不宣称独立 backend mapping gate 或 visible gate。
2. `scroll_selecter` 的 selected-index / edit-mode 合同已落地，backend `kind` 与 shared data-model metadata 已收平到 `PICOUI_BACKEND_WIDGET_SCROLL_SELECTER`，不再是开放缺口。

当前结论边界：

1. `a-0.4` 可以写成“输入 shared-core 主路径已落地到主仓”。
2. 不能把 `keyboard` 写成 dedicated visible / mapping / runtime 三层证据都已经完全对称。
3. 当前更准确的口径是：shared-core 路径已完成，final release 仍依赖总线级 truth-source、manual artifact 和最终总审计。
