## a-0.9 线定位

`a-0.9` 是 PicoUI 对 LingDongGUI 原生能力的 `allowlist truth closeout` 线。

`a-0.8` 已完成 native API exhaustiveness：

1. `src/gui/ld*.h` public API inventory 已覆盖 `611` 行。
2. matrix 已覆盖 `611` 行。
3. 当前状态为 `covered=404 / allowlisted=207 / missing_gap_total=0`。
4. `docs/ability/` 已逐行写入 PicoUI 覆盖状态。

`a-0.9` 不再寻找未建账 API。它只处理最新比对暴露出的真实边界：`207` 个 `allowlisted` 行不是 PicoUI direct public wrapper 覆盖，当前不能被笼统写成 “PicoUI 100% direct 覆盖 LingDongGUI 全部原生 API”。

## a-0.9 做什么

1. 将 `allowlisted` 行拆成可机器校验的 policy category。
2. 对 lifecycle / show / backend-private helper 行建立 `policy-covered internal` 口径，避免继续把已决策内部行显示为 `parity_incomplete`。
3. 对 `keyboard weak hook`、`button action`、`background/root semantics` 做真实能力决策。
4. 需要用户态暴露的能力，补 PicoUI public API、backend proof、unit/gate、matrix row。
5. 不需要用户态暴露的能力，写 strict allowlist rationale，并让 checker 验证其 `required=false`、reason、policy category。
6. 同步 `docs/ability/`，让每个 group 能清楚区分 direct covered、policy-covered internal、仍需开发。

## a-0.9 不做什么

1. 不把 `allowlisted` 直接改名成 `covered`。
2. 不把 lifecycle/show/internal helper 强行包装成 PicoUI public API。
3. 不把 artifact existence 写成人工验收通过。
4. 不用截图/demo 存在替代 backend-field/unit 证据。
5. 不重做 a-0.8 的 API extractor 和 ledger 基线。

## 串行阶段

1. `R0`：policy schema 冻结
   - 定义 `group_kind`、`policy_category`、`policy_covered_internal`。
   - 更新 checker，让 allowlist 不再只有笼统 reason。
2. `R1`：lifecycle / show policy closeout
   - 覆盖每个 widget 的 `depose / on_load / on_frame_start / on_frame_complete / show`。
   - 证明它们由 PicoUI backend lifecycle/render pipeline owned，不要求 public wrapper。
3. `R2`：runtime/internal group closeout
   - 覆盖 `gui / mem / switch_internal / window_layout_internal`。
   - 将这些 group 从 widget public parity denominator 中分离，但保留 inventory 审计。
4. `R3`：base tree/resource/helper 决策
   - 重点复核 `ldBaseGetParent / GetChildCount / GetChildList / GetNextSibling / NodeAdd / NodeRemove`。
   - 若用户态需要 tree traversal，补 PicoUI API；否则写替代模型和 strict policy。
5. `R4`：keyboard weak hook / button action 决策
   - 对 keyboard layout/callback/user draw 和 button action helper 做 explicit decision。
   - 可移植能力必须补 API；不可移植能力必须给替代能力或稳定拒绝理由。
6. `R5`：background/root semantics
   - 决策 `background` 是否进入 matrix。
   - 若不进入，定义 enum-only/root/window-tree derived policy。
7. `R6`：matrix / docs / gate closeout
   - 同步 matrix、ability docs、serial docs。
   - fresh 运行 contract/runtime/mapping/visible/manual artifact gate。

## 当前可并行窗口

- `R0` 必须先做。
- `R1 / R2` 可在 `R0` 后并行，写面不重叠。
- `R3 / R4 / R5` 可在 `R0` 后并行，但最终 matrix 合流必须串行。
- `R6` 必须最后串行。

## 完成定义

`a-0.9` 完成时必须满足：

1. `611` 行 native API 仍全部在 inventory / matrix / ability docs 中。
2. `covered` 行仍有 PicoUI API/backend/unit/gate 证据。
3. `allowlisted` 行全部带 policy category，且 checker 验证 `required=false` 与非空 rationale。
4. widget 级状态不再因为 lifecycle/show/internal policy 行误报 `parity_incomplete`。
5. `keyboard weak hook / button action / background root semantics` 已有明确开发或拒绝决策。
6. 文档不再把 `allowlisted` 写成 direct 100%，也不把 manual artifact existence 写成人工验收通过。
