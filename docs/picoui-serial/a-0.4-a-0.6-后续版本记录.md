# PicoUI a-0.4 到 a-0.6 后续版本记录

## 目的

这份文件只做一件事：

把 `a-0.4 / a-0.5 / a-0.6` 怎么干先记录下来，防止 `a-0.3` 做完以后路线断掉。

当前边界：

1. 这里只记录后续版本定义。
2. 这里只冻结版本目标、控件范围、shared 依赖、完成定义。
3. 这里不展开成后续详细 spec。
4. 这里不展开成后续详细 plan。

## 最终总目标

最终总目标不变：

1. PicoUI 覆盖 LingDongGUI 当前 `26` 个可封装控件。
2. PicoUI 每个控件与对应 `ld*` 控件完整功能对齐。
3. 最终不接受 `wrapped`、`stable contract`、`minimal vertical slice` 作为完成口径。

## a-0.4 输入与选择 shared-core 版

### 目标

建立 PicoUI 后续高耦合输入控件所需的 shared-core。

### 主攻控件

1. `line_edit`
2. `keyboard`
3. `combo_box`
4. `scroll_selecter`

### 关键 shared 依赖

1. focus ownership
2. editable text contract
3. keyboard bridge
4. selection / navigation contract
5. dropdown contract

### 完成定义

`a-0.4` 完成时至少要满足：

1. 上述 `4` 个控件进入 PicoUI public widget 集。
2. 输入/选择 shared-core 不再靠局部 demo 逻辑支撑。
3. `line_edit / keyboard / combo_box / scroll_selecter` 都有真实 backend mapping。
4. unit / contract / mapping / visible 证据齐全。
5. current matrix 与文档同步更新。

### 主要风险

1. `line_edit` 与 `keyboard` 会互相卡住。
2. `combo_box` 与 `scroll_selecter` 会碰 shared selectable/navigation 语义。
3. 若这版只接 API 名字、不做 shared-core，后面 `table` 一定返工。

## a-0.5 数据 / 时间 / 表格版

### 目标

建立 PicoUI 后续数据模型类控件所需的 shared model。

### 主攻控件

1. `table`
2. `graph`
3. `calendar`

### 关键 shared 依赖

1. item model
2. editable cell contract
3. graph series model
4. calendar date/grid contract
5. 与 `a-0.4` 输入 shared-core 的联动

### 完成定义

`a-0.5` 完成时至少要满足：

1. `table / graph / calendar` 进入 PicoUI public widget 集。
2. `table` 的 item/edit model 不是 demo 假逻辑。
3. `graph` 的 series/value 合同真实落到底层。
4. `calendar` 的 date/header/grid 合同真实落到底层。
5. matrix、文档、gate 同步收口。

### 主要风险

1. `table` 最容易扩散到 keyboard/edit/focus。
2. `graph` 若只做静态画图，后面还会返工。
3. `calendar` 若只做显示不做真实 date contract，也是假完成。

## a-0.6 仪表 / 复合导航 / 全量对齐审计版

### 目标

补齐剩余复合视觉控件，并完成最终全量 parity audit。

### 主攻控件

1. `arc`
2. `gauge`
3. `icon_slider`
4. `radial_menu`

### 关键 shared 依赖

1. multi-part visual contract
2. angle / pointer / progress contract
3. composite navigation contract
4. animation / visible evidence boundary

### 完成定义

`a-0.6` 完成时至少要满足：

1. 上述 `4` 个控件进入 PicoUI public widget 集。
2. `26/26` 全控件覆盖完成。
3. 所有控件 capability audit 完成。
4. 所有控件最终状态都收敛到完整对齐，不再保留中间态为终态。
5. 全量 gate、全量 closeout、全量中文文档收口完成。

### 主要风险

1. `gauge / arc` 很容易只做视觉主路径，不做完整 getter/readback/contract。
2. `icon_slider / radial_menu` 很容易只做表层交互，不做复合导航语义。
3. 如果这版不做全量审计，就会留下“全覆盖但不全对齐”的假完成。

## 与 a-0.3 的关系

`a-0.3` 当前只负责：

1. 把 current truth-source 做实。
2. 把 current-15 capability audit 做实。
3. 冻结 `a-0.3` closeout 标准。

`a-0.4 / a-0.5 / a-0.6` 当前只记录，不在本阶段展开 detailed spec / plan。

## 何时展开后续详细文档

只有在 `a-0.3` 满足以下条件后，才展开后续详细 spec 和 plan：

1. current public widget 总数明确。
2. current-15 capability audit 完成。
3. matrix / gate / docs 已对齐。
4. `a-0.3` closeout 标准冻结。
