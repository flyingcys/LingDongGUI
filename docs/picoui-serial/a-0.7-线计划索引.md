## a-0.7 线定位

`a-0.7` 是 PicoUI 的 `LingDongGUI native 100% parity` 线。

它不再沿用 `a-0.6 final release contract` 的裁剪口径。`a-0.7` 只接受一个完成定义：

1. LingDongGUI 全部 widget-like 原生控件都进入 PicoUI public API。
2. 每个 `ld*` public setter/getter/init 关键参数、事件、资源、visual、layout/data 能力都有 PicoUI public API 或明确同等抽象。
3. release matrix 不允许保留 `reject / deferred / incomplete_contract`。
4. gate 必须证明 public API、真实 backend 字段、真实 event/data/readback、visible/manual artifact 全部闭环。

## a-0.7 做什么

1. 重建 `native-100` 真相源：从 `src/gui/ld*.h` 自动/人工双重盘点所有 native API。
2. 将 `ldAnimation` 纳入 PicoUI public widget。
3. 建立 native resource bridge：image/mask/font/color/align/padding/key/nav/callback 等原生类型都要有稳定 PicoUI 表达。
4. 把 `a-0.6` 的 13 条 reject 全部转为 support。
5. 补齐未进入 matrix 的原生高级能力。
6. 补齐每个控件 backend-field 级 unit proof。
7. 升级 runtime / mapping / visible / manual artifact gate 到 native-100 口径。
8. 更新中文文档和 closeout，禁止再写成“release contract 子集覆盖”。

## a-0.7 不做什么

1. 不改 LingDongGUI 原生 API 来迁就 PicoUI。
2. 不通过 demo 硬编码、fake renderer、host cache getter、截图外观补丁伪造 parity。
3. 不允许把不想暴露的 native 能力继续写成 reject。
4. 不允许用“PicoUI 是上层 API”作为跳过 native 100% 的理由；这是本线的目标前提。
5. 不允许只改 matrix 数字，不补 API、backend、unit、gate。

## 串行依赖与可并行窗口

固定依赖链：

1. `a-0.7-R0 native inventory / truth-source`
2. `a-0.7-R1 native bridge shared-core`
3. `a-0.7-R2 base / layout / theme / event 100%`
4. `a-0.7-R3~R6 parallel native widget batches`
8. `a-0.7-R7 native-100 matrix / gate / manual artifact`
9. `a-0.7-R8 closeout / docs / release readiness audit`

顺序原因：

1. `R0` 不先冻结，后续 100% 没有边界。
2. `R1 / R2` 不先做 shared bridge，后续每个控件都会重复造类型和事件桥。
3. `R3~R6` 的控件实现可以并行，但只能基于同一个 frozen `R2` baseline。
4. gate 和文档必须最后收口，以代码态为准。

可并行窗口：

1. `R0 / R1 / R2`：必须串行。
2. `R3A / R3B / R4A / R4B / R5A / R5B / R6A / R6B`：可并行开发。
3. `R7 / R8`：必须串行。

并行开发的前提：

1. 每个并行批次使用独立 worktree。
2. 每个并行批次只拥有自己的 header/widget/backend/unit/demo 文件。
3. `picoui/include/picoui/picoui.h`、`tests/picoui/CMakeLists.txt`、release matrix、runtime/mapping/visible/manual gate、`picoui/docs/demo_guide.md` 由主线程或 integration captain 串行合流。
4. 并行 subagent 可以在自己的 worktree 临时改聚合文件验证局部构建，但最终合流时不得直接覆盖其他批次改动。
5. 每个批次必须产出 capability fragment，供 `R7` 合并到 native-100 matrix。

推荐并行 worktree：

1. `.worktree/a-0.7-r3a-text-image`
2. `.worktree/a-0.7-r3b-selection`
3. `.worktree/a-0.7-r4a-input-nav`

## closeout 标准

`a-0.7` 完成时至少满足：

1. `27/27` widget-like 控件进入 PicoUI public API，包含 `animation`。
2. `src/gui/ld*.h` 中所有 public native setter/getter/init 关键参数都在 native-100 matrix 有行。
3. matrix 中 `reject / deferred / incomplete_contract / not_wrapped` 计数全部为 `0`。
4. 所有控件都有 backend-field 级 unit proof。
5. 所有控件都有 runtime / mapping / visible / manual artifact 证据。
6. `message_box` 不再保留 formal mapping exclusion。
7. `keyboard` 不再保留 runtime-first 特例。
8. `temporary smoke path` 不能参与 native-100 结论。
9. 中文 closeout 明确写成 LingDongGUI 原生 100% 能力覆盖，并列出完整 proof set。
