## a-01 线定位

`a-01` 线负责当前已经 `wrapped` 的 PicoUI 控件中，仍未真正收口的 backlog 控件能力补齐。

它的唯一目标不是扩新控件，而是把现有 `5` 个 backlog 控件做实：

- `image`
- `text`
- `checkbox`
- `switch`
- `list`

`a-01` 线是当前 PicoUI 并行拓扑中的 shared-owner 线。凡是容易影响多控件语义的共享层，默认由 `a-01` 持有写权。

## worktree

- 目录：`.worktree/a-01`
- 建议分支：`feat/picoui-a-01-wrapped-backlog`

创建或切换后必须执行：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

## a-01 线做什么

1. 逐个串行收口当前 backlog 控件。
2. 允许修改共享 widget/backend/style/event 合同。
3. 为 backlog 控件补齐 unit / contract / mapping / visible 证据。
4. 收紧已支持能力与 reject/deferred/incomplete_contract 边界。
5. 为主线程提供可小批量 merge-back 的 clean slice。

## a-01 线不做什么

1. 不新增 `progress_bar`、`qrcode`、`message_box`、`line_edit`、`combo_box`。
2. 不把 `H线/J线` 发布 closeout 文档当成当前开发索引去重写。
3. 不靠 demo 硬编码或 fake visual 补丁掩盖 backend 缺口。
4. 不把 `wrapped` 偷换成 parity complete。

## 串行顺序

固定顺序：

1. `a-01-A1 image`
2. `a-01-A2 text`
3. `a-01-A3 checkbox`
4. `a-01-A4 switch`
5. `a-01-A5 list`

顺序原因：

- `image` 合同最薄，先做最容易把 reject/deferred 边界钉死。
- `text` 与字体、背景、readback 合同相关，但交互耦合低。
- `checkbox` / `switch` 都会碰 shared style/event 语义，放在中段连续处理。
- `list` 最容易扩散到 callback、marker、shared backend 口径，必须最后做。

## 与 02 线的隔离规则

1. `a-01` 不碰 `progress_bar`、`qrcode`、`message_box` 新控件文件。
2. `a-01` 只在阶段末尾才修改聚合入口文件。
3. 只要 `a-01` 正在改共享层，`a-02` 不得并行改 shared-owner 文件。
4. `a-02` 若确需接入共享聚合文件，先 rebase 到 `a-01` 最近 checkpoint，再做最小接入。

## 每阶段最小验收

每个 `a-01-Ax` 阶段结束至少执行：

```bash
rtk cmake -S . -B build -DUSE_DEMO=0
rtk cmake --build build
ctest --test-dir build -L picoui --output-on-failure
python3 tests/picoui/contract/check_picoui_public_api.py
git diff --check
```

若阶段改到 mapping / visible / release matrix，再追加：

```bash
ctest --test-dir build -L mapping --output-on-failure
ctest --test-dir build -L visible --output-on-failure
python3 tests/picoui/contract/check_picoui_release_capability_matrix.py
```

注意：

- `runtime / visible / mapping` 共用本 worktree 的 `build/picoui-runtime`。
- `a-01` 内部也不要并行跑这些标签。

## merge-back 节奏

不建议 `a-01` 五个阶段全做完再回灌。推荐三次回灌：

1. `image + text`
2. `checkbox + switch`
3. `list`

每次回灌前主线程至少检查：

```bash
git status --short --branch --ignore-submodules=all
git diff --stat
git diff --check
```

## 当前正确口径

- `a-01` 线是 backlog 收口线，不是发布 closeout 线。
- `a-01` 线可以提升当前 PicoUI 覆盖率和合同密度，但不自动等于 `release ready`。
- `a-01` 线任何阶段都必须继续遵守 `unit / contract / mapping / visible / manual_artifact` 五层证据边界。
