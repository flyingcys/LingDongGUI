## a-0.5 线定位

`a-0.5` 线不是“把剩下三个高价值控件补上”。

它是 PicoUI 的数据 / edit model 线，只做一件事：

1. 先把 item model 与 editable cell contract 做实。
2. 再在这套 model 上串行接入 `table / graph / calendar`。

## worktree

- 目录：`.worktree/a-0.5`
- 建议分支：`feat/picoui-a-0-5-data-model`

创建或切换后必须执行：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

## a-0.5 线做什么

1. 冻结 item model。
2. 冻结 editable cell contract。
3. 收口 `0.4` 输入 shared-core 与数据模型的联动边界。
4. 串行接入 `table`。
5. 串行接入 `graph`。
6. 串行接入 `calendar`。
7. 收口 matrix / gate / 中文文档。

## a-0.5 线不做什么

1. 不做 `arc / gauge / icon_slider / radial_menu`。
2. 不先做 `graph` 或 `calendar` 再回头补 `table`。
3. 不允许继续扩散 host cache getter 模式。
4. 不允许只靠 visible 证明“像表格/像日历/像图表”。

## 严格串行顺序

固定顺序：

1. `a-0.5-R0 item model baseline`
2. `a-0.5-R1 editable cell contract`
3. `a-0.5-R2 table`
4. `a-0.5-R3 graph series / value model + graph`
5. `a-0.5-R4 calendar date / header / grid contract + calendar`
6. `a-0.5-R5 matrix / gate / docs closeout`

顺序原因：

1. `table` 最早暴露 edit model 是否真实。
2. `graph` 与 `calendar` 都应复用 shared model / truth policy，而不是各自造结构。
3. 若 `R0 / R1` 不过，后续三控件全部会返工。

## subagent 串行拓扑

推荐拓扑：

1. 主线程
   - 冻结 shared model 边界
   - 跑 GitNexus impact
   - 收敛 matrix / gate / 文档
   - 做最终验证
2. `SG-0.5-R0`
   - 只做 item model baseline
3. `SG-0.5-R1`
   - 只做 editable cell contract
4. `SG-0.5-R2`
   - 只做 `table`
5. `SG-0.5-R3`
   - 只做 `graph`
6. `SG-0.5-R4`
   - 只做 `calendar`
7. `SG-0.5-Review`
   - 每阶段独立 review

规则：

1. 任意时刻只允许一个写 subagent。
2. `table` 阶段不过，不允许开 `graph / calendar`。
3. review 不通过时，由同阶段 subagent 修复。

## 每阶段最小验收

每阶段结束至少执行：

```bash
rtk cmake -S . -B build -DUSE_DEMO=0
rtk cmake --build build
ctest --test-dir build -L picoui --output-on-failure
python3 tests/picoui/contract/check_picoui_public_api.py
git diff --check
```

涉及 matrix / runtime / visible / mapping 时，再追加：

```bash
python3 tests/picoui/contract/check_picoui_release_capability_matrix.py
python3 tests/picoui/runtime/check_picoui_backend_mapping.py
python3 tests/picoui/runtime/check_picoui_visible_ui.py --all
python3 tests/picoui/runtime/check_picoui_runtime.py
```

对 `R0 / R1 / R2` 必须额外验证：

1. frame/event 后数据真值不漂移
2. editable cell 与 keyboard/line_edit 桥接无状态错乱
3. getter / visible / backend truth 三者一致

## closeout 标准

`a-0.5` 完成时至少要满足：

1. `table / graph / calendar` 全部进入 PicoUI public widget。
2. `table` 证明 item model 与 editable cell contract 真实成立。
3. `graph` 证明 series / value 模型真实落到底层。
4. `calendar` 证明 date / header / grid 合同真实落到底层。
5. `a-0.6` 可以把重心放到复合视觉与最终全量审计，而不是回头返工 `0.4 / 0.5` shared-core。
