# PicoUI a-0.8：v0.7 native-100 review 缺口清单

日期：2026-06-02

## 结论

`v0.7` 不能诚实写成“100% 控件覆盖 + 对应控件 100% 能力覆盖”。

当前可成立的结论是：

1. `v0.7` 已把 `ldBase.h` 里的 `27/27` widget-like 类型纳入 PicoUI 盘点。
2. `v0.7` 已补大量 public API、backend 映射、unit、runtime、mapping、visible、manual artifact 证据。
3. 但 `v0.7` 的 native-100 gate 仍主要验证“手写 inventory / matrix 自洽”，没有从 `src/gui/ld*.h` 自动抽取每个 public init / setter / getter / callback / weak hook 后逐项证明 PicoUI API 和 backend truth 覆盖。
4. 因此 `v0.7` 的 `full_parity_complete=27` 只能视为当前手写矩阵口径，不等于 LingDongGUI 原生控件能力 100%。

`a-0.8` 必须作为 native API exhaustiveness 修正线：先让 gate 能发现遗漏，再补真实 public API、backend-field proof、unit/gate 证据。

## v0.7 已做到的部分

1. 控件类型覆盖：`tests/picoui/contract/check_picoui_native_100_inventory.py` 会解析 `src/gui/ldBase.h` 的 `ldWidgetType_t`，并断言 widget-like 总数为 `27`。
2. matrix 自洽：`tests/picoui/contract/check_picoui_release_capability_matrix.py` 会断言 matrix 与 inventory 的 widget 名称集合一致，且 `27` 个 widget 都标为 `full_parity_complete`。
3. gate catalog 覆盖：runtime / mapping / visible / manual artifact catalog 已包含 `animation_basic` 等 `a-0.7` demo 入口。
4. 代码覆盖面扩大：`picoui/include/picoui/animation.h`、`picoui/src/widgets/animation.c`、`picoui/src/backend/ldgui/backend_animation.c` 已新增；多个已有控件也新增了资源、读回和事件接口。

这些证据能证明“27 个 widget-like 类型进入 v0.7 盘点”，不能证明“每个 `ld*` public 能力 100% 覆盖”。

## 阻断 100% 结论的系统性问题

### 1. native inventory gate 没有逐项抽取 `ld*.h` public API

证据：

1. `tests/picoui/contract/check_picoui_native_100_inventory.py:51` 只解析 `ldBase.h` 的 `ldWidgetType_t`。
2. `tests/picoui/contract/check_picoui_native_100_inventory.py:100` 只要求每个 widget 至少有一个 `required_native_capabilities`。
3. `tests/picoui/contract/picoui_native_100_inventory.json:10` 起每个 widget 只有粗粒度能力描述，例如 `window` 只有 `init_layout_background / flex_grid_padding_gap / background_image_mask` 三项。
4. `tests/picoui/contract/check_picoui_release_capability_matrix.py:165` 起只校验 matrix row 自称 `full_parity_complete / support / final_release_ready`，没有反向比对 `src/gui/ld*.h` 中的所有 public function。
5. `tests/picoui/contract/check_picoui_public_api.py:84` 起只遍历 PicoUI public header 并检查 `ld* / arm_2d_* / SIGNAL_*` 禁泄漏和命名前缀，不校验 native API 是否全覆盖。

缺口：

1. `a-0.8` 必须新增 `ld*.h` public API extractor。
2. extractor 至少输出每个 widget 的 `init / depose / lifecycle / show / setter / getter / callback / weak hook / macro alias` 分类。
3. matrix 必须从 extractor 结果派生，不能只靠手写 capability 名称。
4. 每个 native API row 必须绑定 `picoui_api`、`backend_proof`、`unit_test`、`gate_evidence` 或明确 `out_of_scope_with_reason`。`a-0.8` native-100 目标下默认不允许 out-of-scope。
5. `check_picoui_public_api.py` 必须升级为双向合同：既禁止 native 符号泄漏，也要求 PicoUI public API 与 native inventory 的 required rows 对齐。

### 2. `text` 控件明显未覆盖 `ldText` public 能力

证据：

1. `src/gui/ldText.h:82` 到 `src/gui/ldText.h:91` 暴露 `ldTextSetTransparent / SetText / SetStaticText / SetTextColor / SetFont / SetConsumedFont / SetBackgroundImage / SetBackgroundColor / ScrollSeek / ScrollMove`。
2. `picoui/include/picoui/text.h:24` 到 `picoui/include/picoui/text.h:28` 只有 create、props create、`picoui_text_set_text`、`picoui_text_set_font`。
3. `picoui/include/picoui/text.h:9` 到 `picoui/include/picoui/text.h:22` 的 props 有 `bg_color / text_color / border_color / radius / padding`，但没有 explicit transparent、static text、consumed font、background image/mask、scroll seek/move。
4. matrix 中 `text` 只有 `create_and_props / text / font_minimal_mapping / bg_and_text_color` 四项能力。

缺口：

1. 补 `picoui_text_set_transparent` 与 backend field proof。
2. 补 `picoui_text_set_static_text`，明确 ownership / lifetime 合同。
3. 补 `picoui_text_set_text_color`、`picoui_text_set_bg_color` 的 public API 或证明 widget/theme 同等抽象会直接落到 `ldText` 字段。
4. 补 `picoui_text_set_background_source`，覆盖 `ldTextSetBackgroundImage` 的 image + mask。
5. 补 `picoui_text_set_consumed_font` 或明确 consumed font 与 normal font 的等价/差异。
6. 补 `picoui_text_scroll_seek`、`picoui_text_scroll_move`。
7. 为以上每项补 backend-field unit，不只补 visible demo。

### 3. `image` 控件缺少 mask color public 能力

证据：

1. `src/gui/ldImage.h:63` 到 `src/gui/ldImage.h:64` 暴露 `ldImageSetImage` 和 `ldImageSetMaskColor`。
2. `picoui/include/picoui/image.h:28` 到 `picoui/include/picoui/image.h:31` 只有 create 和 `picoui_image_set_source`。
3. `picoui/src/backend/ldgui/backend_image.c:59` 到 `picoui/src/backend/ldgui/backend_image.c:76` 只调用 `ldImageSetImage`，没有落 `ldImageSetMaskColor`。

缺口：

1. 补 `picoui_image_set_mask_color`。
2. `picoui_image_source` 或 native bridge 需要统一表达 mask color，避免 image / qrcode / clock 等控件各自定义。
3. 单测必须断言 `ldImage_t.maskColor` 被真实写入。

### 4. `window` 的 layout public API 仍不完整

证据：

1. `src/gui/ldWindow.h:139` 到 `src/gui/ldWindow.h:153` 暴露 `ldWindowSetLayout / FlexFlow / FlexAlign / FlexTrackAlign / Padding / FlexGap / Gap / GridColumns / GridDscArray / GridAlign / GridGap / GridPadding / PaddingGroup`。
2. `picoui/include/picoui/layout.h:27` 到 `picoui/include/picoui/layout.h:39` 只暴露 flex flow/align/gap 和 grid columns/rows/gap/align。
3. `picoui/include/picoui/window.h:28` 到 `picoui/include/picoui/window.h:38` 只暴露 background source、padding group 和 padding group getter。
4. 没有看到对应 `ldWindowSetLayout`、`ldWindowSetPadding`、`ldWindowSetGridPadding`、`ldWindowSetGap` 的完整 public API 对等入口。

缺口：

1. 补显式 `picoui_window_set_layout` 或证明 flex/grid setter 会严格等价设置 layout type。
2. 补 `picoui_window_set_padding` 和 `picoui_window_set_grid_padding` 的 public API。
3. 补 `picoui_window_set_gap` 的 generic gap 语义，或明确它被 `picoui_flex_set_gap / picoui_grid_set_gap` 完整覆盖。
4. 单测必须覆盖 `ldWindow_t.layoutTpye / flexPadding / gridPadding / flexGap / gridRowGap / gridColumnGap` 等真实字段。

### 5. `line_edit` 缺少 align / color public 能力

证据：

1. `src/gui/ldLineEdit.h:73` 到 `src/gui/ldLineEdit.h:78` 暴露 `SetText / SetKeyboard / SetType / SetAlign / SetColor / GetText`。
2. `picoui/include/picoui/line_edit.h:37` 到 `picoui/include/picoui/line_edit.h:49` 暴露 text、type、keyboard binding、editing、finished callback。
3. line_edit public API 没有 `picoui_line_edit_set_align` 或专用 `picoui_line_edit_set_color`。

缺口：

1. 补 `picoui_line_edit_set_align`。
2. 补 `picoui_line_edit_set_color`，或把 text/background/frame color 三元组明确映射到 widget/theme 并做 backend proof。
3. finished callback 还要明确是否覆盖 LingDongGUI finished reason；若没有 reason，`a-0.8` 需要补 reason enum。

### 6. `keyboard` 只覆盖操作入口，未覆盖 native hook/customization 面

证据：

1. `src/gui/ldKeyboard.h:94` 到 `src/gui/ldKeyboard.h:101` 暴露 navigate、target button list weak hook、callback weak hook、button user draw weak hook、update、button update、click、exit。
2. `picoui/include/picoui/keyboard.h:22` 到 `picoui/include/picoui/keyboard.h:28` 只有 create、ascii input、navigate、click、exit。

缺口：

1. 明确 weak hook 是否属于 native-100 范围。若属于，补 `target button list / callback / user draw` 的 PicoUI abstraction。
2. 补 `picoui_keyboard_update`、`picoui_keyboard_button_update` 或证明这些是 runtime 内部行为，不属于 public parity。
3. gate 需要断言 keyboard 事件不是 runtime-first 特例，也不是仅靠 demo 操作闭环。
4. `tests/picoui/contract/native_100_fragments/r4a-input-nav.json:38` 到 `tests/picoui/contract/native_100_fragments/r4a-input-nav.json:49` 目前只把 keyboard capability 限定为 `ascii_input / navigate / click / exit / editing_owner_priority / mapping / visible`，却标记 support；这不足以覆盖 `ldKeyboard.h` 的 hook/update 面。

### 7. 多个控件存在“PicoUI API 多于 ld setter，但不等于原生 public 能力证明”的风险

例子：

1. `qrcode`：`picoui/include/picoui/qrcode.h:24` 到 `picoui/include/picoui/qrcode.h:28` 暴露 qr color、bg color、ecc、max version、zoom；`src/gui/ldQRCode.h:72` 只有 `ldQRCodeSetText`，其他参数主要来自 init 字段。`picoui/src/backend/ldgui/backend_qrcode.c:116` 起直接写 `ldQRCode_t` 字段。这个实现可能可接受，但 matrix 必须把“init-only field write”与“public setter”分开标注，不能笼统写 support。
2. `slider`：`src/gui/ldSlider.h:72` 到 `src/gui/ldSlider.h:77` 有 percent、orientation、image、color、indicator width、slim size；`picoui/include/picoui/slider.h:42` 到 `picoui/include/picoui/slider.h:55` 没有专用 color setter，需证明 theme/widget color 是否完整覆盖 `ldSliderSetColor` 三色语义。
3. `button`：`src/gui/ldButton.h:90` 到 `src/gui/ldButton.h:98` 有多项 getter；`picoui/include/picoui/button.h:41` 到 `picoui/include/picoui/button.h:48` 只覆盖 transparent/checkable/key/pressed getter，缺 font/text/textColor/releaseColor/pressColor getter 的 parity 决策。

缺口：

1. matrix row 需要区分 `native setter parity`、`init parameter parity`、`direct field parity`、`PicoUI higher-level equivalent`。
2. 对 direct field write 必须有 unit proof 和 rationale，不能默认算 setter parity。
3. 对 getter 缺失必须补 PicoUI getter，或在 native-100 目标中写明 readback policy 并通过 checker enforce。

### 8. 旧人工验收事实源仍保留 v0.7 special-case 冲突

证据：

1. `docs/picoui-serial/C-线人工窗口验收记录.md:303` 写明 `message_box_basic` 仍保留 formal mapping exclusion 特例，不能外推出普通静态 mapping 结论。
2. `docs/picoui-serial/C-线人工窗口验收记录.md:339` 写明 `keyboard_basic` 仍带 `keyboard` fake fallback 特例，不能外推出 dedicated mapping/visible 已独立闭环。
3. `tests/picoui/contract/picoui_release_capability_matrix.json:1115` 将 `manual_artifact` 标为 `manual_review_required`，但同一 widget 仍给 `final_release_ready / full_parity_complete`。

缺口：

1. `a-0.8` 必须清理或重录 `message_box_basic / keyboard_basic` 的 manual evidence，不能让旧 C 线 special-case 与 v0.7 native-100 closeout 同时存在。
2. matrix 必须区分 `artifact_entry_exists`、`manual_review_required`、`manual_reviewed_passed`、`capability_complete`。artifact 存在和待人工验收不能等同 100%。
3. 若 manual review 未实际完成，closeout 只能写“artifact 已生成，人工验收待做”，不能写 final release ready。

### 9. temporary smoke path 仍存在，不能参与 native-100 结论

证据：

1. `picoui/src/backend/ldgui/backend_app.c:592` 仍存在 `picoui_backend_apply_smoke_cursor_layout()`。
2. `picoui/src/backend/ldgui/backend_app.c:602` 注释写明这是 `temporary smoke layout` 的 explicit opt-in 路径。
3. `a-0.7` 设计要求不依赖 fake renderer、demo 私有状态或 temporary smoke path，但当前代码仍保留可触发路径。

缺口：

1. `a-0.8` gate 必须检测 full parity demo 是否触发 `picoui_backend_apply_smoke_cursor_layout()`。
2. 需要保留 smoke path 时，必须从 native-100 formal mapping / visible / manual 结论中剥离。
3. closeout 必须明确 smoke path 只服务 runtime harness，不服务控件能力完成证明。

## a-0.8 必须交付的文件/门禁

### 必须新增或升级

1. `tests/picoui/contract/ldgui_public_api_inventory.json`
2. `tests/picoui/contract/check_ldgui_public_api_inventory.py`
3. `tests/picoui/contract/check_picoui_native_api_exhaustiveness.py`
4. `tests/picoui/contract/picoui_release_capability_matrix.json`
5. `tests/picoui/contract/check_picoui_release_capability_matrix.py`

### checker 必须证明

1. 从 `src/gui/ld*.h` 自动抽取 `ld[A-Z].*` public function。
2. 按 widget 分类每个 public API。
3. 忽略项必须在 allowlist 中逐项列 reason，默认 fail。
4. 每个非忽略 native API 必须有 matrix row。
5. 每个 matrix row 必须有 public PicoUI API 或明确同等抽象。
6. 每个 matrix row 必须有 backend truth proof。
7. 每个 row 的 unit test 名称必须真实存在于 `tests/picoui/unit/`。
8. `manual_artifact` 仍只能表示 artifact 存在和待人工验收，不能当人工验收通过。
9. full parity demo 不得触发 `temporary smoke layout`，触发即 fail。
10. 旧 serial truth-source 中的 special-case 记录必须被 fresh evidence 替换，不能与 closeout 结论冲突。

### v0.8 第一批修复优先级

1. `text`：补 static/transparent/background/scroll/consumed-font。
2. `image`：补 mask color。
3. `window/layout`：补 layout type、padding/grid padding/generic gap 对等 API。
4. `line_edit`：补 align/color/finished reason。
5. `keyboard`：决策并补 weak hook/update/button update 能力。
6. `slider/button/qrcode`：把 direct field / init-only / getter readback policy 写成机器可校验矩阵，不再用笼统 support。
7. `message_box/keyboard`：重录 mapping/manual evidence，移除旧 special-case 冲突。
8. `backend_app.c`：给 smoke cursor layout 加 native-100 禁触发 gate，或彻底从 full parity demo 路径移除。

## a-0.8 完成定义

`a-0.8` 完成前禁止写“100% 控件与能力覆盖”。只有同时满足以下条件后才允许：

1. `ldgui_public_api_inventory.json` 覆盖所有 `src/gui/ld*.h` public API。
2. `check_picoui_native_api_exhaustiveness.py` 通过，且 allowlist 为空或只含明确非 widget public API。
3. `picoui_release_capability_matrix.json` 的 capability rows 与 public API inventory 完全对齐。
4. 本文列出的 `text / image / window / line_edit / keyboard / slider / button / qrcode` 缺口全部关闭。
5. `message_box / keyboard / backend_app.c smoke path / manual_artifact` 的证据冲突全部关闭。
6. `ctest --test-dir build -L picoui --output-on-failure` 通过。
7. `python3 tests/picoui/contract/check_picoui_public_api.py` 通过。
8. `python3 tests/picoui/contract/check_picoui_native_100_inventory.py` 通过。
9. `python3 tests/picoui/contract/check_picoui_release_capability_matrix.py` 通过。
10. `python3 tests/picoui/contract/check_picoui_native_api_exhaustiveness.py` 通过。
11. runtime / mapping / visible / manual artifact gate 全部通过，且不把 artifact existence 写成人工验收通过。
