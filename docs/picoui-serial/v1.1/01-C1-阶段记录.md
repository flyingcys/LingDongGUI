# PicoUI v1.1 C1 阶段记录

## 当前目标

- 冻结删除边界
- 建立新的 core/header/build 骨架
- 为 C2 垂直切片准备最小着陆点

## 当前红线

- `picoui_app_*` 已冻结为 v1.1 删除目标，不做新增兼容层；真实删除与 umbrella 收口放到后续阶段完成
- `picoui/src/native/` 与 `picoui/src/backend/` 将在 C5 真删，但 C1 起不再允许新代码依赖它们
- 不允许把 `ldBase/ldScene/ldMsg/SIGNAL/control_node` 搬进 PicoUI 新骨架

## 当前 reality

- `app.h` 仍是当前 legacy app API 的真实声明源；`picoui_v1_1_boundary_contract` 现在同时约束删除清单和 `app.h`/`picoui.h` 的现态一致性
- `runtime.h` 与 `indev.h` 仍是当前 runtime/input 声明真相源；`core.h`、`input.h` 只作为 v1.1 新入口别名，不重复定义接口
- `C1-C` 已把 `picoui_init` / `picoui_deinit` / `picoui_timer_handler`、`picoui_screen_*`、`picoui_indev_create` 的 public 符号接管到 `picoui/src/core/*.c` wrapper；`picoui/src/native/*.c` 现阶段只保留内部 `*_impl` 实现，行为保持不变

## 当前完成

- 已创建 `picoui_core_v1_1`、`picoui_widgets_v1_1`、`picoui_port_v1_1` 这三个 v1.1 target 名称骨架
- `picoui_widgets_v1_1` 当前仅由构建期生成的 placeholder 源维持非空 target，不携带任何真实 widget 实现
- `picoui_port_v1_1` 当前只是名称/接口层占位 target，未连接到真实 port stack，也不回挂旧 `picoui_port_sdl` / `picoui_core`

说明：当前完成的是 target/名称层的最小骨架，不代表已经形成独立可链接、可消费的 v1.1 stack；现有 `picoui` target 与旧链路仍是当前真实实现。
