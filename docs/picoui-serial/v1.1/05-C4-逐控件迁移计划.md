# PicoUI v1.1 C4 逐控件迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `core` 已稳定的前提下，逐控件从 `src/gui` 借算法迁入 `picoui/src/widgets/`，让每个控件都以 PicoUI 自己的 state/render 为 authority。

**Architecture:** 本阶段按控件族分组推进，而不是一次性全量搬迁。每组都遵循同一套路：先写 focused test 锁定可观察语义，再借 `src/gui` 算法重写到 PicoUI 风格实现中，最后验证 getter 不再读 backend mirror，render 不再经 `native/backend` 层。

**Tech Stack:** C11, CMake, ARM-2D, SDL2, PicoUI widgets/core, `rtk cmake`, `rtk ctest`, Python runtime checks.

## 控件分组策略

- `G1 基础状态控件`：checkbox / switch / slider
- `G2 文本与资源控件`：text / image / line_edit / keyboard / canvas
- `G3 容器与列表控件`：list / table / scroll_selecter / combo_box / message_box
- `G4 可视复杂控件`：graph / gauge / progress_bar / progress_wheel / radial_menu / qrcode
- `G5 时间与复合控件`：calendar / clock / date_time / animation / background / icon_slider

每个组都要独立 closeout；同组内可以一控件一 subagent，但写面不得重叠。

- [ ] **Step 4: 借算法重写实现**

迁移规则：

- `checkbox`：只借勾选状态和基础绘制算法，不借旧 signal 系统。
- `switch`：借 `ldSwitch` 的 animation/knob-track 几何与推进算法，但改成 `picoui_switch_*` 风格函数和本地 state。
- `slider`：借 track/thumb/value 公式，但不保留 backend readback。

必须满足：

```c
int picoui_switch_get_checked(const struct picoui_switch *sw)
{
    return (sw == 0) ? 0 : sw->checked;
}
```

这种 getter 直接读本地 state，不读 backend。

- [ ] **Step 5: GREEN**

```bash

rtk ctest --test-dir build -R test_picoui_v1_1_checkbox_switch_slider --output-on-failure
rtk rg -n "picoui_backend_|backend/ldgui|ldMsg|SIGNAL_" picoui/src/widgets/checkbox.c picoui/src/widgets/switch.c picoui/src/widgets/slider.c
rtk git diff --check
```
