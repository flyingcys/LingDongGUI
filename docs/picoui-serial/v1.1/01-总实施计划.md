# PicoUI v1.1 Clean Small GUI 总实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement the phase plan documents task-by-task. This file is the dispatcher index; do not use it as the only execution context for a subagent.

**Goal:** 将 PicoUI 从 `native/backend` 叠层重构为真正独立、轻量、单心智的小型 GUI，形成 `public API -> widgets -> core(hidden) -> arm2d/port` 默认实现链。

**Architecture:** 本线不做“一次性大爆破”。先冻结架构和删除边界，再建立最小 `core` 骨架与一条 `window/label/button` 垂直链，之后补 `layout/focus/theme` 公共机制，再逐控件从 `src/gui` 借算法迁入 `widgets`，最后统一移除 `native/backend` 目录与旧构建残留。

**Tech Stack:** C11, CMake, SDL2, ARM-2D, PicoUI public headers, `rtk cmake`, `rtk ctest`, Python contract checks, GitNexus impact/detect_changes.

## 阶段门禁

- `C1 gate`：默认构建图已经有新的 `picoui core + widgets + port` 命名与最小入口，且删除项已被 contract 明确约束。
- `C2 gate`：`basic_widgets` 跑通 `window/label/button` 最小链，且按钮状态/render 不再依赖 backend truth。
- `C3 gate`：flex/grid、focus、dirty、theme 最小集合通过 focused tests，不再调用 `native/backend` helper。
- `C4 gate`：目标控件全部以 PicoUI 本地 state/render 为 authority，getter 不再读 backend mirror。
- `C5 gate`：默认 `picoui` target 不再包含 `picoui/src/native/` 与 `picoui/src/backend/`，相关目录已删，文档/tests/demo 全部切到 `v1.1` 真相。

## Subagent Dispatch 建议

- `C1`：最多 2 个串行 subagent。一个做 contract/build red-line，一个做 core skeleton；两者写面不要重叠。
- `C2`：最多 3 个串行 subagent。`window`、`label`、`button/input/render` 可拆，但必须在同阶段按依赖顺序收敛。
- `C3`：按 `tree/dirty`、`layout`、`focus/theme` 三条子线串行推进，每条线内部可再按任务拆 subagent。
- `C4`：按控件族拆。基础控件与复杂控件分线，写面不得重叠。
- `C5`：主线程主导收口，必要时用单独 subagent 做 docs/gates，但不要并行改相同清单文件。
