# PicoUI v1.1 C2 阶段记录

## C2-A 目标

- 只收口 `window -> label child tree` 最小真相。
- focused native test 必须只走 public v1.1 路径，不再手工调用 `picoui_native_widget_bind_child()`。
- `picoui_window_create_root(screen, "root")` 使用当前真实双参数签名，不改 public header。

## 当前 reality

- 现有 `picoui_widget_get_parent/first_child/next_sibling/root` 与 `picoui/src/native/native_widget.c` 绑定表路径已经存在。
- 现有 `picoui_screen_load(screen)` 会调用 `picoui_native_widget_bind_root()`，因此这轮不需要重写 `struct picoui_widget`，也不需要改 `runtime_state.h`。
- 当前缺口在 child wrapper 创建后没有把 host widget 绑定回 backend tree，导致 `screen_load()` 递归时看不到 `label` child。

## C2-A 红线

- 不进入 C2-B/C2-C/C2-D。
- 不改 `picoui_window_create_root` public 签名，不扩散 header。
- 不重写 widget/core/native 架构，只复用现有 backend tree + native_widget bind/query 路径。
- 不把 render/layout/theme 收口伪装成这一轮目标。

## C2-A 收口策略

- 新增 focused native test：`root + label_a + label_b + picoui_screen_load(screen)` 后断言 `parent/first_child/next_sibling/root`。
- 实现只补最小 host 绑定，让现有 `screen_load -> picoui_native_widget_bind_root` 能把 backend child tree 映射回 PicoUI wrapper tree。

## C2-B 目标

- 只收口 `label` 文本状态的 PicoUI 本地 truth，不扩成新的 render framework。
- focused native test 必须走当前 public `screen_load -> timer_handler` 路径，并证明 `picoui_label_get_text()` 至少对 PicoUI 自己的文本状态成立。
- 若 dirty/render 语义在当前结构下没有稳定公共证据，这一轮不虚构断言。

## 当前 reality

- 当前 `picoui_widget_set_text()` 只写 `widget->text`，不标 dirty，也不会反推 backend。
- 当前 `picoui_label_set_text()` 先写 `picoui_widget_set_text()`，再调用 backend `set_text`；因此 setter 会让本地与 backend 同步，但这不代表 getter 可以继续只读 backend。
- 当前 `picoui_label_get_text()` 仍从 backend readback 取值；一旦 public 路径只更新 PicoUI 本地 `widget->text`，getter 就会和 PicoUI 自己状态矛盾。
- 当前 `picoui_timer_handler()` 已走既有 native runtime/render/event 主链；仓库已有大量 native dirty/render 测试，这一轮不重塑该框架，也不新建 `picoui/src/core/render.c`。

## C2-B 红线

- 不进入 C2-C/C2-D。
- 不把 `picoui_timer_handler()` 改写成新的 dirty 清理框架。
- 不为迎合旧计划样例而新建占位 `render.c` 或扩散到 button / generic widget getter。
- 不把 backend readback 偶然一致当成 PicoUI 本地 truth。

## C2-B 收口策略

- 新增 focused native test：先 `picoui_label_set_text()` 建立现有 backend 路径，再用公开 `picoui_widget_set_text()` 覆盖本地 truth，断言 `picoui_label_get_text()` 必须回到 PicoUI 自己状态。
- 测试补一轮 `picoui_screen_load(screen)` 与 `picoui_timer_handler()`，确认当前 public load/timer 路径后 getter 结果仍不自相矛盾。
- 实现只把 `picoui_label_get_text()` 改为读取 `label->widget.text`，保持现有 setter、screen load、native render 主链不变。

## C2-C 目标

- 只收口 `button` 的本地 `pressed/click` authority，不扩成真实 input dispatch 或 backend 按钮绘制。
- focused native test 必须证明 `pressed` 状态以 PicoUI 本地字段为准，并且 click 只在 `1 -> 0` 边沿触发一次。
- `set_on_clicked(NULL, user_data)` 必须允许解绑定，不能把“无回调”错误化。

## 当前 reality

- `picoui_button_create()` 已走 `v1.1` 本地 child-tree append 路径，不再要求 backend widget 才能创建。
- `picoui_button_set_pressed()` 现在只修改 PicoUI 本地 `pressed` 与 `dirty`，并在 release 边沿触发已注册 click callback。
- `picoui_button_get_pressed()` 通过输出参数返回 PicoUI 本地 `pressed`，不读 backend readback。

## C2-C 红线

- 不进入 `C2-D` 或 `C3`。
- 不把按钮 click authority 伪装成真实 pointer dispatch、focus 导航或 backend 视觉完成。
- 不恢复对旧 `button.c` / `backend_button.c` readback 的依赖。

## C2-C 收口策略

- focused native test 覆盖：
  - `set_on_clicked(button, 0, 0)` 合法解绑定
  - `0 -> 0` 与 `1 -> 1` 不重复触发 click
  - 重新注册回调后，`1 -> 0` 只触发一次 click
  - `dirty` 在每次 `set_pressed()` 后置 1
- 实现只保留 `pressed/click` 的 PicoUI 本地 authority，不扩出 `text/render/layout` 额外范围。

## C2-D 目标

- 把 `picoui/demo/basic_widgets/main.c` 收口成 `v1.1` 最小样板，只保留 `window + label + button`。
- runtime checker 必须证明该样板源码边界正确，并且 fresh build 后能在 `SDL_VIDEODRIVER=dummy + PICOUI_DEMO_AUTO_QUIT_MS=1200` 下输出 `PICOUI_RUNTIME_READY` 后正常退出。
- `basic_widgets` target 必须真实链到 `picoui_v1_1`，不能继续吃 legacy `picoui + picoui_port_sdl` 旧链。

## 当前 reality
