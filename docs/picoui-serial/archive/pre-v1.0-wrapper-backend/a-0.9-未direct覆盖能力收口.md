# PicoUI a-0.9：未 direct 覆盖能力收口文档

日期：2026-06-02

## 结论

基于最新 `docs/ability/` 与 `tests/picoui/contract/picoui_release_capability_matrix.json` 比对，当前 PicoUI 对 LingDongGUI 原生 API 的状态是：

1. `ldgui_public_api_total=611`。
2. `covered=404`：这些行已有 PicoUI API / backend proof / unit / gate 证据。
3. `allowlisted=207`：这些行已进入 ledger，但不是 PicoUI direct public wrapper 覆盖。
4. `missing_gap_total=0`：当前没有未建账的 native API 行。
5. `207` 个 allowlisted 行全部是 `required=false`，不能简单写成“用户态能力缺 207 个”；但也不能写成 PicoUI 已 direct 100% 覆盖。

因此 `a-0.9` 的目标不是重做 a-0.8，而是把 `allowlisted` 行做真实性收口：

1. 对确实应该保持内部的 lifecycle / show / helper / runtime 行，建立可机器校验的 policy 和文档，不再让它们把 widget 标成 `parity_incomplete`。
2. 对仍可能是用户可见能力的 hook / action / background/root 语义，做真实设计决策；需要暴露则补 PicoUI API、backend proof、unit/gate，不需要暴露则写 strict allowlist rationale 和 checker。
3. 最终让 release 结论能区分 `direct covered`、`policy-covered internal`、`manual-not-passed`，避免把 allowlist 混成 covered。

## 最新缺口分类

| 类别 | 数量 | 当前状态 | a-0.9 处理方向 |
| --- | ---: | --- | --- |
| lifecycle / show | 135 | widget 生命周期和 render/show 入口，当前 allowlisted | 建立 lifecycle/show policy，证明 PicoUI backend owns lifecycle，不要求 public wrapper；matrix 从 `parity_incomplete` 改为 policy-complete。 |
| scene/runtime/internal groups | 35 | `gui/mem/switch_internal/window_layout_internal` 等非 widget public API | 分组确认：runtime host、memory、layout solver、switch geometry 是否全部非 PicoUI user-facing；补 checker/文档。 |
| base tree/resource/helper | 30 | `ldBase` tree/resource/date/time/helper 等非 direct wrapper | 拆成 `must expose` 与 `internal helper`；对 tree/parent/child 若要支持用户态 traversal，要补 API；否则 strict allowlist。 |
| keyboard weak hook / button action | 5 | native weak hook、draw callback、nameId action helper | 这是最像真实能力缺口的一组：必须做 abstraction 决策。可移植则补 API；不可移植则写不可暴露原因和替代能力。 |
| background/root semantics | 1 concept | `background` 无独立 matrix group | 需要新增 background/root 语义 proof 或正式定义为 window/tree 派生能力；不能继续只有文字边界。 |

## a-0.9 必须收口的能力组

### L1：lifecycle / show policy

范围：每个 widget 的 `*_depose / *_on_load / *_on_frame_start / *_on_frame_complete / *_show`。

当前问题：这些行被 allowlist 后仍让每个 widget 显示 `parity_incomplete`。这会导致“没有 missing gap”与“仍 incomplete”同时存在。

a-0.9 处理：

1. 新增 matrix 状态或 judgment：`policy_covered_internal`。
2. checker 要求 lifecycle/show 行必须满足：
   - `required=false`。
   - `coverage_kind` 是 `lifecycle_internal_allowlisted` 或 `non_widget_allowlisted`。
   - `allowlist_reason` 指明由 backend lifecycle/render pipeline owned。
   - 不允许空 reason。
3. widget 级 `parity_status` 不能因为这些行单独保持 `parity_incomplete`。

### L2：scene/runtime/internal groups

范围：`gui / mem / switch_internal / window_layout_internal`。

当前问题：这些 group 不是独立 widgetType，却在 matrix 里参与 `parity_incomplete`。其中有些是 runtime host 能力，有些是 layout/switch solver helper。

a-0.9 处理：

1. 给每个 group 标 `group_kind`：`widget / shared_base / runtime_host / internal_helper / enum_only`。
2. `runtime_host / internal_helper` 不参与 PicoUI public widget parity 百分比，但必须参与 native API inventory 审计。
3. checker 要求这些 group 的 allowlist reason 和 group_kind 匹配。
4. 若发现用户态需要的 runtime 能力，例如 page navigation 或 root lifecycle，要单独建 PicoUI app/runtime API，而不是藏在 allowlist。

### L3：base tree/resource/helper 能力

范围：`base` 的 30 条 allowlisted 行。

当前问题：`ldBaseGetChildCount / GetChildList / GetParent / GetNextSibling / NodeAdd / NodeRemove` 等 tree 能力可能是用户可见结构能力；`GetVresImage / GetVresFont / GetDate / GetTime / GetWeek` 可能是 resource/time helper。现在统一 allowlist 太粗。

a-0.9 处理：

1. 把 base allowlist 拆成：
   - tree traversal / parent-child management
   - resource lookup
   - date/time helper
   - drawing helper
   - layout/helper math
2. 对 tree traversal 做明确决策：
   - 如果 PicoUI 用户需要 introspection，补 `picoui_widget_get_parent / child_count / child_at / next_sibling` 等 API 和 unit。
   - 如果 PicoUI 不暴露树遍历，写明替代模型和不可暴露原因。
3. 对 resource/time/drawing helper，若保持 backend-private，checker 必须验证它们不会出现在 public parity denominator。

当前 R3 决策（2026-06-02）：不新增 PicoUI tree traversal public API。

1. `ldBaseGetParent / ldBaseGetChildCount / ldBaseGetChildList / ldBaseGetNextSibling / ldBaseGetWidget* / ldBaseNodeAdd / ldBaseNodeRemove` 保持 `base_tree_policy`。
   - PicoUI 用户态建树模型已经由各 `picoui_*_create(parent, ...)` / props create 表达 parent intent。
   - backend 负责真实 `LingDongGUI` attach/remove，`tests/picoui/unit/test_picoui_widgets.c` 的 `test_backend_widget_tree_contract` 已验证 backend child/sibling tree ownership。
   - `picoui_backend_list_set_item_widget()` 对 list item 复用 `ldBaseNodeRemove/ldBaseNodeAdd` 维护真实 native tree；这是 backend implementation detail，不是 public wrapper surface。
2. `ldBaseGetVresImage / ldBaseGetVresFont / ldBaseGetDate / ldBaseGetTime / ldBaseGetWeek` 保持 `resource_time_helper_policy`。
   - 这些是 LingDongGUI host resource/time helper；PicoUI 继续通过 widget-specific portable props/API 表达 image/font/date/time intent，不暴露 raw address/time helper。
3. `ldBaseDrawLine / ldBaseImageScale / ldBaseColor / ldBaseImage / ldBaseLabel` 保持 `drawing_helper_policy`。
   - 这些是 raw Arm-2D drawing/render helpers；PicoUI 通过 widget/theme/image abstraction 表达用户意图，不新增公共 drawing primitive wrapper。
4. 结果：`base` group 从 `parity_incomplete` 收敛为 `policy_complete_not_direct_100 / policy_complete`，但这不是 direct 100% covered。

### L4：keyboard weak hook / button action

范围：

- `keyboard.ldKeyboardGetTargetBtnList`
- `keyboard.ldKeyboardCallback`
- `keyboard.ldKeyboardBtnUserDraw`
- `button.ldButtonActionInit`
- `button.ldButtonActionIsPressById`

当前问题：这些不是普通 lifecycle/show；它们可能表达真实扩展能力、custom draw、callback 或 global action 查询。若 PicoUI 要做到更强 native parity，这组最需要重新设计。

a-0.9 处理：

1. keyboard hook 决策：
   - `target button list`：是否允许用户提供 key layout。
   - `callback`：是否需要 PicoUI keyboard event callback。
   - `user draw`：是否允许自定义 key paint 或仅支持 style/theme。
2. button action 决策：
   - 是否需要 `picoui_button_action_bind_name_id` 或 event/action abstraction。
   - 若不暴露 native global `nameId` 查询，必须提供等价的 PicoUI event/readback API。
3. 每个被暴露的能力都必须有 public API、backend proof、unit、matrix row。

当前 R4 决策（2026-06-02）：不新增 native weak hook / nameId action public API。

1. `ldKeyboardGetTargetBtnList` 保持 `backend_private_hook`。
   - native `kbBtnInfo_t` button list 含布局、tile、mask 等 backend-specific detail；PicoUI 不暴露该结构。
   - PicoUI 用户态意图由 `picoui_keyboard_input_ascii / navigate / update / button_update / click / exit` 与 line_edit/text editing owner 机制覆盖。
2. `ldKeyboardCallback` 保持 `backend_private_hook`。
   - native weak callback 属 backend hook；PicoUI 通过 widget event abstraction 与 keyboard input/navigation API 表达交互，不包装弱符号。
3. `ldKeyboardBtnUserDraw` 保持 `backend_private_hook`。
   - raw Arm-2D tile draw callback 不具可移植性；PicoUI 只通过 style/theme/widget abstraction 做视觉定制。
4. `ldButtonActionInit / ldButtonActionIsPressById` 保持 `native_action_private`。
   - native helper 依赖 global `nameId` action wiring；PicoUI 已有 per-widget `on_pressed / on_released / on_clicked` callback 和 `picoui_button_get_press/get_pressed` readback。
5. 证据：`tests/picoui/unit/test_picoui_keyboard.c` 的 `test_keyboard_weak_hooks_remain_backend_private_not_public_api` 与 `tests/picoui/unit/test_picoui_button_events.c` 覆盖 backend-private/native-action policy。`button`、`keyboard` group 已进入 `policy_complete_not_direct_100 / policy_complete`。

### L5：background/root semantics

当前问题：`background` 是 `widgetTypeBackground`，但没有独立 header/API group，也没有独立 matrix group。`docs/ability/background.md` 已写明不能虚构 direct 100%。

a-0.9 处理：

1. 决策 `background` 是否需要 PicoUI public abstraction。
2. 若需要，新增 root/background capability rows：root background type、root container、background child semantics。
3. 若不需要，正式定义为 `window/tree derived enum-only`，并让 checker 接受 enum-only policy。

当前 R5 决策（2026-06-02）：不新增独立 PicoUI background public abstraction。

1. `background` 没有独立 `ldBackground.h` public API group，不新增虚构 setter/getter。
2. root/background semantics 正式定义为 `window/tree derived enum-only` policy。
3. `ldWindowInit / ldWindow_init` 继续保持 `enum_only_semantics`，原因是 PicoUI 通过 `picoui_window_create`、window color/background source/layout API 和 backend root tree ownership 表达用户意图。
4. `docs/ability/background.md` 已同步该边界；`window` group 已进入 `policy_complete_not_direct_100 / policy_complete`。
