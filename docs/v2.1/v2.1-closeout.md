# TinyUI v2.1 Closeout

## 当前口径

本文档当前承载 `V3` 阶段的 closeout truth：`V3 Step 3` 已在 2026-06-12 完成 fresh 验证，但这仍不等同于 `v2.1` 全阶段最终 release closeout。

在 `V5` 完成前，这里的结论只证明：

- shared layer include path / target naming 已收口到 `tinyui` 产品层子系统
- shared layer retention 是有意设计，不是 backend 残留杂质
- backend removal 没有把 shared responsibilities 粗暴塌缩进 widgets

当前不证明：

- `V4` 的 demo/test/contract/CMake/perf artifact 命名迁移已经完成
- `V5` 的最终 release matrix / release-facing truth 已经完成

`V5` 仍需继续补齐：

- 最终 release matrix
- `v2.1` performance baseline 文档
- 最终 broad gates 与 release-facing truth

## 当前已完成内容

### 1. shared layer 已按产品层 `tinyui` 子系统收口

当前 shared/product-layer 真相已经稳定在以下子系统：

- `tinyui/src/core`
- `tinyui/src/display`
- `tinyui/src/indev`
- `tinyui/src/layout`
- `tinyui/src/theme`
- `tinyui/src/tick`
- `tinyui/src/osal`

对应 include path 已统一走 `tinyui/include/*` wrapper 入口，不再让 shared 源码层直接依赖旧 `picoui/...` include path。

### 2. shared layer retention 是有意设计

`V3` 的目标不是把 shared logic 再次塌缩进 widgets，而是把 shared 层的产品命名、internal/shared seam、target naming 收口到 `tinyui`。

当前 shared layer 继续保留，是因为它仍承载真实共享职责，例如：

- runtime bridge / runtime host
- display / indev / tick / osal
- shared theme/layout/native conversion
- shared widget-tree / event / value-dispatch internal seam

这条边界是有意设计，方向更接近 LVGL 风格的“共享基础设施 + widget 实现”，而不是“backend 清零后所有逻辑都回灌到单个 widget 文件”。

### 3. backend removal 没有把 shared responsibilities 粗暴塌缩进 widgets

`V2` 已完成 backend-to-widgets compile-surface cleanup，但这不等于 shared responsibilities 消失。

当前真相是：

- widget-local backend seam 已按 widget 收回对应 `tinyui/src/widgets/*`
- shared responsibilities 继续保留在 `tinyui/src/core/*`、`layout/*`、`theme/*`、`display/*`、`indev/*`、`tick/*`、`osal/*`
- `V3` 继续做的是 shared/internal 命名和 target 收口，而不是回退到第二轮“把 shared 层继续拆散进 widgets”
