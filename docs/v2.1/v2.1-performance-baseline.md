## Binary Size

- checker：`python3 tests/tinyui/perf/check_tinyui_binary_size.py`
- baseline：`tests/tinyui/perf/tinyui_perf_baseline.json -> binary_size`
- artifact：`build/tinyui-runtime/examples/sdl/tinyui_basic_widgets_demo`
- 工具选择顺序：`xcrun llvm-size --format=sysv` -> `llvm-size --format=sysv` -> `size`
- 判定方式：每个指标使用“双阈值并联放行”，只有增长字节数同时超过百分比阈值和绝对字节阈值时才失败

| 指标 | baseline | 百分比阈值 | 绝对字节阈值 |
| --- | ---: | ---: | ---: |
| `__text` | `121844` | `5%` | `8192` |
| `__data` | `272` | `25%` | `256` |
| `__bss` | `98768` | `10%` | `8192` |
| `total` | `231400` | `5%` | `12288` |

## Runtime Perf

- checker：`python3 tests/tinyui/perf/check_tinyui_perf.py`
- baseline：`tests/tinyui/perf/tinyui_perf_baseline.json -> benchmark.runtime_perf.metrics`
- benchmark 载体：`build/tinyui-runtime/examples/sdl/tinyui_basic_widgets_demo`
- 口径说明：
  - `screen_object_create_ms`：`picoui_screen_create()` 返回 root screen object 的创建耗时；只覆盖 runtime public API 侧对象创建
  - `capture_ready_ms`：`picoui_screen_load()` 后到 `PICOUI_CAPTURE_FILE` 可读且尺寸有效的耗时；证明“capture ready”，不宣称完整首帧渲染

| 指标 | baseline | 上限 |
| --- | ---: | ---: |
| `screen_object_create_ms` | `0.0 ms` | `5.0 ms` |
| `capture_ready_ms` | `20.0 ms` | `40.0 ms` |

## Wrapper Struct Overhead

- checker：`python3 tests/tinyui/perf/check_tinyui_object_overhead.py`
- baseline：`tests/tinyui/perf/tinyui_perf_baseline.json -> benchmark.wrapper_struct_overhead.metrics`
- probe target：`test_tinyui_wrapper_struct_overhead`
- 口径说明：
  - 这是 ABI-bound struct footprint guard
  - 只量编译期 `struct` 布局大小
  - 不量 runtime heap、native widget 实例树或 allocator bookkeeping

| 指标 | baseline | 上限 |
| --- | ---: | ---: |
| `widget_wrapper_struct_bytes` | `184` | `192` |
| `switch_wrapper_struct_delta_bytes` | `32` | `32` |
| `backend_widget_struct_bytes` | `496` | `512` |

## Blocking Policy

- `binary_size`、`runtime_perf`、`wrapper_struct_overhead` 任一 gate 越线，必须阻塞 `V5` 最终 closeout / release 结论
- baseline 缺项、schema 漂移、checker 回退到隐式默认值，也必须阻塞 `V5`
- `runtime_perf` 与 `wrapper_struct_overhead` 仍是窄口径 gate：
  - 不外推完整首帧渲染时间
  - 不外推整体 RAM 成本
  - 不外推所有控件族的总性能结论

## 当前真实 gate

- self-test / focused：
  - `python3 tests/tinyui/perf/check_tinyui_binary_size.py`
  - `python3 tests/tinyui/perf/check_tinyui_perf.py --self-test`
  - `python3 tests/tinyui/perf/check_tinyui_object_overhead.py --self-test`
- broad perf：
  - `rtk ctest --test-dir build -L 'perf' --output-on-failure`
- runtime / visible / backend mapping：
  - `rtk ctest --test-dir build/tinyui-runtime -R 'check_tinyui_runtime|check_tinyui_visible_ui|check_tinyui_backend_mapping' --output-on-failure`

## 当前结论

- 当前可以保守确认：
  - `v2.1` 的 canonical perf baseline 已迁到 `tests/tinyui/perf/tinyui_perf_baseline.json`
  - `binary_size`、`runtime_perf`、`wrapper_struct_overhead` 三条守门线都已有 `tinyui` canonical checker 与 baseline
  - `tests/picoui/perf/*` 当前只保留 compat thin wrapper，不再是主线真相源
- 当前不能外推成以下结论：
  - 完整首帧渲染时间已经被证明
  - 整体 RAM 成本或所有控件族开销已经被证明
  - 仅凭 perf 绿灯就能替代 `v2.1` 的 contract/runtime/visible/closeout 全量完成证据
