# TinyUI v2.1 Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改 `LingDongGUI` 目录与 `ld*` public API 的前提下，彻底消灭产品层 `PicoUI` 痕迹，把当前 `picoui/` 原地演化为唯一的 `tinyui/` 产品目录，并完成目录、命名、backend、demo、tests、contracts、CMake 与文档的全量收口。

**Architecture:** 按串行文档线执行迁移：`V0` 先冻结 `v2.0` 末态 inventory 并建立 rename/目录 guards；`V1` 把顶层目录和 public header 收口到唯一 `tinyui/`；`V2` 删除独立 `backend` 并把 widget-specific 对接逻辑并回 `widgets/*`；`V3` 统一 shared layer 的命名与 include path；`V4` 全量迁移 demo/test/contract/CMake；`V5` 删除剩余 `picoui` 痕迹并完成 closeout/release 收口。每个阶段都必须先过 focused tests + broad gates + docs update，再进入下一阶段。

**Tech Stack:** C11、CMake、CTest、Python 3、SDL2、Arm-2D、现有 `LingDongGUI` core、当前 `picoui/tinyui` 代码与 `docs/v2.0` 真相源。

当前阶段状态：

- `v2.0` 已完成过渡态收口：`backend` shared layer 被拆平、`app` 退出用户主路径、`tinyui_*` 试点 public surface 落地、`P5/P6` gate 与 closeout 真相闭环
- `v2.1` 的任务不是继续做 alias，而是消灭产品层 `picoui` 痕迹并完成真正的 `tinyui/` 顶层收口
- `LingDongGUI` 继续作为 engine truth，不进入本次 rename 范围
